## 1. 项目定位与心智模型

### 1.1 一句话定位
> **Crafts-Island（手艺岛）：一座亲手打造的个人小岛 —— 学习、自律与生活，都在这里。**

三端互通（Web + Windows + Android）个人小岛，Java + Python 双后端，云端 MySQL 为唯一数据源。

### 1.2 心智模型：岛 + 岛民
不用"工具箱"（功能堆砌），用"岛"（有归属、可生长、有画面感）。

```
          ┌────────────────────────────────────────────┐
          │             手艺岛 · Crafts-Island           │
          │           （内核 = 岛基座，只做必需的事）        │
          │  ┌─────────┐  ┌─────────┐  ┌─────────┐        │
          │  │ 📚 学习计划│  │ 🍅 专注计时│  │ 📝 笔记   │  ← 岛民(插件)
          │  └─────────┘  └─────────┘  └─────────┘        │
          │  ┌─────────┐  ┌─────────┐  ┌─────────┐        │
          │  │ 🔐 密码  │  │ 📦 资源库 │  │ 🥗 减脂  │  ← 岛民(插件)
          │  └─────────┘  └─────────┘  └─────────┘        │
          │  ┌─────────┐  ┌─────────┐  ┌─────────┐        │
          │  │ 🎬 影音  │  │ ✈️ 旅行  │  │ 📌 备忘  │  ← 岛民(插件)
          │  └─────────┘  └─────────┘  └─────────┘        │
          │  ┌────────────────────────────────────┐        │
          │  │ ⭐ GitHub 收藏  ← 也是岛民（示例）     │        │
          │  └────────────────────────────────────┘        │
          └────────────────────────────────────────────┘
```

**岛基座（内核）只做三件事**：身份与权限、三端同步、插件装载（注册/启用/禁用）。其余全是可插拔的岛民。

### 1.3 设计原则
1. **内核稳定、岛民可换**：改一个岛民不影响内核与其他岛民。
2. **统一规矩、克制扩展**：每个岛民遵循同一套数据/接口/前端规范。
3. **边做边学、一座岛一座岛地盖**：每完成一个岛民都有落地感，学习路线与开发进度对齐。

## 2. 总体架构（现状目标形态）

### 2.1 分层总览

```
┌─────────────────────────────────────────────────────────────┐
│  三端入口（同一套业务代码）                                     │
│  🌐 Web 网页端      🖥️ Windows 桌面端(Tauri)   📱 Android(UniApp) │
└───────────────────────────┬─────────────────────────────────┘
                            │ 实时双向同步
┌───────────────────────────▼─────────────────────────────────┐
│  后端双引擎                                                    │
│  ☕ Java SpringBoot（核心业务）      🐍 Python FastAPI（工具）   │
│    用户/鉴权/同步/事务/加密            图表/数据分析/MD解析/导出   │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  数据与缓存层                                                  │
│  🗄️ MySQL（业务持久化 · 唯一数据源）      ⚡ Redis（缓存加速）    │
└─────────────────────────────────────────────────────────────┘
  横切：🔒 AES 加密 · 🖧 三端同步 · 🚀 Linux + Nginx 部署
```

### 2.2 技术栈清单

| 层 | 技术 | 职责 |
|----|------|------|
| 后端主引擎 | Java SpringBoot + MyBatis | 核心业务接口、用户鉴权、事务、加密 |
| 后端工具引擎 | Python FastAPI | 图表、数据分析、Markdown 解析、PDF 导出 |
| 前端 | Vue3 + Vite + Element Plus + Axios | Web 管理端；供桌面/移动复用 |
| 桌面端 | Tauri | Windows 打包、本地离线缓存 |
| 移动端 | UniApp | Android APK、移动端适配 |
| 数据 | MySQL | 业务持久化，唯一数据源 |
| 缓存 | Redis | 会话缓存、临时同步、性能优化 |
| 安全 | AES / JWT | 密码密文存储、登录鉴权 |
| 部署 | Linux + Nginx | 前后端分离、反向代理 |

### 2.3 数据流（一次典型请求）
```
前端(任一入口) → Nginx → SpringBoot/FastAPI → MySQL/Redis → 返回 {code,msg,data}
   ↑                                                     ↓
   └────────────── 三端同步(离线缓存+冲突处理) ←──────────┘
```

## 3. 插件化架构（核心设计）

> 目标形态：让新功能在**不修改内核代码**的前提下被装载/卸载。分三步演进（见第 10 节），本节描述最终形态，落地时按阶段推进。

### 3.1 内核（岛基座）职责
| 职责 | 说明 | 归属 |
|------|------|------|
| 用户与鉴权 | 注册/登录/JWT/会话 | SpringBoot 内核 |
| 权限体系 | 角色 + 插件可见性控制 | SpringBoot 内核 |
| 三端同步 | 统一同步协议、离线缓存、冲突处理 | 内核服务 |
| 插件注册表 | 记录已装载岛民、版本、启用状态 | MySQL 表 + Redis 缓存 |
| 动态路由/菜单 | 根据注册表生成菜单与路由 | 前端内核 |
| 统一返回格式 | `{code, msg, data}` 契约 | 双后端内核 |

### 3.2 插件（岛民）职责
| 组成 | 说明 |
|------|------|
| 后端 Java 模块 | 一个独立 SpringBoot Starter / 模块包，`@Configuration` 自动装配 |
| 后端 Python 路由组 | 一个 FastAPI `APIRouter` 子路由，注册进主应用 |
| 前端页面组 | 一组 Vue 组件 + 动态路由 + 菜单入口 |
| 数据表 | 独立数据表，**表名带插件前缀**，版本化 SQL + 迁移脚本 |
| 插件清单 | 名称、版本、图标、入口、依赖表、权限说明 |

### 3.3 插件生命周期
```
开发/打包 → 注册(写入插件注册表) → 启用(默认) → 使用
                │                        │
                └── 停用(隐藏入口)   ←────┘
                └── 卸载(移除注册表，保留数据或归档)
```

### 3.4 插件清单规范（manifest，示意）
```json
{
  "id": "study-plan",
  "name": "学习计划",
  "version": "0.1.0",
  "icon": "📚",
  "entry": "/study",
  "backend": {
    "java_module": "plugin-study-plan",
    "fastapi_router": "study"
  },
  "tables": ["study_task", "study_record"],
  "permissions": ["study:read", "study:write"],
  "enabled": true
}
```

## 4. 分层与模块规范

### 4.1 后端 Java（SpringBoot）
- **统一返回格式**：所有接口返回 `{ "code": 0, "msg": "ok", "data": {...} }`；`code=0` 成功，非 0 见错误码表（预留）。
- **统一异常**：全局异常处理器，业务异常用自定义异常类，避免到处 try/catch。
- **统一鉴权**：JWT 拦截器校验登录态；插件接口声明所需权限。
- **分层**：`controller / service / mapper / entity`；插件模块可带 `config`（自动装配）。
- **事务**：写操作按业务边界加 `@Transactional`。

### 4.2 后端 Python（FastAPI）
- **路由分层**：每个插件一个 `APIRouter(prefix="/plugin/{id}")`，主应用 `include_router`。
- **统一响应**：复用 `{code, msg, data}` 契约，提供公共 response model。
- **定位**：只承载轻量工具（图表、解析、统计），不承担核心事务。

### 4.3 前端（Vue3）
- **动态路由**：路由由"内核路由 + 插件路由（按注册表）"合并生成。
- **菜单权限**：菜单项随插件启用状态与用户权限动态渲染。
- **页面规范**：每插件一个目录 `src/views/plugins/<id>/`，内部组件化。

### 4.4 数据与缓存
- **MySQL**：插件表带前缀（见第 5 节）；所有表通用字段统一。
- **Redis**：key 统一 `crafts:<domain>:<key>`；会话 `crafts:session:*`；插件注册表缓存 `crafts:registry:*`。
- **迁移**：每个插件自带版本化 SQL（`V1__xxx.sql` 风格），有简单迁移脚本或手动记录版本。

## 5. 数据表设计规范

### 5.1 通用字段（所有表必备）
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INT / BIGINT | 主键，自增 |
| `create_time` | DATETIME | 创建时间，`DEFAULT CURRENT_TIMESTAMP` |
| `update_time` | DATETIME | 更新时间，随更新刷新（约定） |

### 5.2 命名约定
- 表名小写、下划线分隔；**插件表带前缀**：`study_`、`note_`、`pwd_`、`repo_` 等。
- 字段名小写下划线；布尔用 `is_` 前缀（如 `is_done`）。
- 所有字段带 `COMMENT`（好习惯，零基础课程也在教）。

### 5.3 关联
- 与用户相关表都含 `user_id` 外键。
- 跨插件不直接引用对方表，通过用户 + 主键 ID 关联（保持插件解耦）。

### 5.4 已落地对照
| 表 | 前缀 | 状态 |
|----|------|------|
| `user`（内核） | — | 🟢 `sql/01_用户表设计.sql` |

## 6. 三端同步机制

- **唯一数据源**：云端 MySQL 是唯一可信源。
- **离线缓存**：桌面端/移动端本地缓存最近数据，联网后自动同步。
- **冲突处理**：以 `update_time` 或"最后写入者胜"策略；复杂场景预留冲突标记待用户选择（后期）。
- **同步契约**：内核提供统一的增量同步接口（`/sync/pull`、`/sync/push`），插件只提供各自数据的序列化，不各自实现同步逻辑。
- **原则**：同步是内核能力，岛民不重复造轮子。

## 7. 安全设计

| 项 | 方案 |
|----|------|
| 登录 | JWT 无状态鉴权 + Redis 会话 |
| 密码存储 | AES 对称加密，密文入库，无明文泄露 |
| 插件权限 | 接口声明所需权限，内核拦截校验 |
| 数据脱敏 | 敏感字段前端脱敏展示 |
| 传输 | HTTPS + Nginx TLS（部署阶段） |

## 8. 部署架构

```
用户 → Nginx(80/443, 反向代理+TLS)
         ├── /api → SpringBoot（Java 进程）
         ├── /tool → FastAPI（Python 进程）
         └── /  → Vue3 静态资源
后端进程 → MySQL、Redis（同机或云托管）
```
- Linux 云服务器，前后端分离部署。
- 插件以内核内部模块/路由形式打包，不额外增加进程（保持部署简单）。

## 9. 插件开发指南（给未来的自己）

### 9.1 新增一个岛民的 checklist
1. 写插件清单 manifest（id / name / version / icon / entry / tables / permissions）。
2. 设计数据表（带前缀 + 通用字段 + COMMENT），写版本化 SQL。
3. 后端：Java 模块或 FastAPI 路由组，按统一返回格式实现 CRUD。
4. 前端：页面组件 + 动态路由 + 菜单入口。
5. 注册到插件注册表，启用，三端自测。
6. 更新本架构文档的插件清单与状态。

### 9.2 最小示例骨架（示意）
```
plugins/
  study-plan/
    manifest.json
    sql/V1__init.sql
    backend-java/   (或 backend-py/router.py)
    frontend/        (views + router)
```
